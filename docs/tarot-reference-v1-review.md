# RWS 해설 자료와 배열 통합: 편집·검증 기록

이 변경은 78장에 대해 루니아용으로 작성한 정방향 의미, 역방향 의미, 과잉 해석 방지 기준을 제공한다. 역사적 원전의 번역이나 전문가 감수 완료 데이터로 표시하지 않는다. 현행 해석 전통에도 여러 차이가 있으므로 특정 역방향 해석을 유일한 정답으로 취급하지 않는다.

원전 확인에 사용한 자료:
- A. E. Waite, The Pictorial Key to the Tarot, [메이저 해석](https://sacred-texts.com/book/the-pictorial-key-to-the-tarot/shell/section-3-the-greater-arcana-and-their-divinatory-meanings)
- [Four of Cups](https://sacred-texts.com/book/the-pictorial-key-to-the-tarot/shell/four-of-cups)
- [The Art of Tarot Divination](https://sacred-texts.com/book/the-pictorial-key-to-the-tarot/shell/section-6-the-art-of-tarot-divination)

위 원전 일부를 대조했으며 78장 전체의 독립 문헌 교차검증 완료를 주장하지 않는다. 현대의 회복·내면화 해석 등은 루니아 편집적 해석이다. 질병·죽음·외도·성별 등을 카드에서 사실로 확정하는 오래된 단정을 그대로 적용하지 않는다. 타로 상징의 해석 일관성과 실제 사건 예측의 정확성은 별개다.

## 구현

- 실제 덱 코드 78개와 코드가 없는 저장 기록 이름을 연결한다. Pentacles의 내부 코드 Pents와 표준 영어 표기를 함께 지원한다.
- 현재 나온 카드와 해당 방향의 자료만 전송한다. 보조 카드는 본 카드 번호에 연결한다.
- 자료 파일은 reading 기능 그룹에서 최종 프롬프트 조립 전에 로드한다.
- 이전 질문의 자료 블록은 교체하고, 원래 카드·포지션·방향·추첨 상태는 수정하지 않는다.
- 미확인 또는 상충하는 카드 정체는 다른 카드로 대체하지 않는다.
- 자료는 프롬프트 규칙이다. 최종 생성 답변이 항상 이를 준수한다고 보장하지 않는다.

## 실제 생성 평가 절차

`tests/fixtures/tarot-expert-evaluation-v1.json`의 12개 사례는 **아직 생성·채점하지 않았다**. 각 사례에 동일 모델/설정으로 이전 프롬프트와 새 프롬프트를 각각 3회 생성해 비교한다. 모델 ID, 프롬프트 버전, 날짜, 온도, 입력, 출력 전체를 기록한다. 유료 API 키가 작업 환경에 제공되지 않아 이번 작업에서 실제 Gemini 호출은 하지 않았다.

사례마다 다음 항목을 0/1/2로 수동 평가한다. 0=위반/누락, 1=부분 충족, 2=근거를 명시하며 충족.

1. 모든 질문 축에 직접 답했는가?
2. 카드·정역방향·포지션·본/보조 관계가 정확한가?
3. 선택한 의미를 포지션과 연결한 이유가 있는가?
4. 반증을 숨기지 않고 결론과 연결했는가?
5. 감정·의도·행동을 구별하며 근거 없는 사실·날짜를 만들지 않았는가?
6. 한국어가 자연스럽고 중복된 일반론이 적은가?

카드나 방향을 바꾸거나, 확인되지 않은 외도·죽음 등 사건을 확정하거나, 날짜·확률을 날조한 경우 총점과 무관하게 실패로 기록한다. 점수는 해설 준수도 평가이며 예측 적중률이 아니다. 입력을 숨긴 채 전후 답변을 무작위 순서로 평가하고, 모델 자체 채점만으로 품질 향상을 확정하지 않는다.
